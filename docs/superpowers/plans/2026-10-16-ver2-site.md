# veR2 Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static marketing + documentation site for veR2 in `site/`, built with Next.js 16 and shadcn/ui defaults.

**Architecture:** `site/` is a private npm workspace (`@ver2/site`). Next.js App Router with `output: "export"` produces plain HTML. Docs pages are MDX files under `app/docs/<slug>/page.mdx`, ordered by one list in `lib/docs-nav.ts`. A Vitest drift test reads the MDX and the SDK/CLI source so the docs fail the build when they fall behind the code.

**Tech Stack:** Next.js 16.4, React 19.3, TypeScript strict, Tailwind v4 + `@tailwindcss/typography`, shadcn/ui 4.22 (default preset), `next-themes`, `@next/mdx`, `rehype-pretty-code` + Shiki, `rehype-slug`, `rehype-autolink-headings`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-ver2-site-design.md`

**Content tasks:** Tasks 6–9 write prose. Their steps give the exact page outline, required facts and sources; the prose is written at execution time from those sources and every code sample is checked against the real API (`sdk/src/index.ts`, `cli/src/main.ts`). Do not invent options, flags or behavior.

> **Execution notes (Tasks 1–2):** create-next-app 16.4.2 wires Tailwind v4 as a Turbopack loader in `next.config` (no PostCSS config), so `next.config.mjs` must keep its `turbopack.rules["*.css"]` entry. The template also enables `cacheComponents` / `partialPrefetching`; drop them, because PPR cannot run with `output: "export"`. Bare plugin names are plain strings (`"rehype-slug"`), per the bundled MDX guide. `mdx-components.tsx` is required as soon as any MDX page exists, so a minimal one lands in Task 2 and Task 4 replaces it. The shadcn default preset is `base-nova` (Base UI) and uses the `cn` package. `*.tsbuildinfo` is git-ignored.

`site/test/docs-drift.test.ts`:
```ts
import { existsSync, readdirSync, readFileSync } from "node:fs";
import { join, relative, sep } from "node:path";
import { fileURLToPath } from "node:url";
import { describe, expect, it } from "vitest";
import { docsNav } from "../lib/docs-nav";

const root = fileURLToPath(new URL("..", import.meta.url));
const docsDir = join(root, "app", "docs");

/** "/docs/installation/" for app/docs/installation/page.mdx; "/docs/" for app/docs/page.mdx. */
function pageHrefs(): string[] {
  return readdirSync(docsDir, { recursive: true })
    .map(String)
    .filter((f) => f.endsWith("page.mdx"))
    .map((f) => {
      const dir = relative(docsDir, join(docsDir, f, "..")).split(sep).filter(Boolean).join("/");
      return dir ? `/docs/${dir}/` : "/docs/";
    })
    .sort();
}

export const readDoc = (slug: string) => readFileSync(join(docsDir, slug, "page.mdx"), "utf8");
export const readRepo = (path: string) => readFileSync(join(root, "..", path), "utf8");

describe("docs navigation", () => {
  it("lists every docs page exactly once", () => {
    const hrefs = docsNav.map((item) => item.href);
    expect(new Set(hrefs).size).toBe(hrefs.length);
    expect([...hrefs].sort()).toEqual(pageHrefs());
  });

  it("uses trailing-slash hrefs that match the static export", () => {
    for (const item of docsNav) expect(item.href).toMatch(/^\/docs\/([a-z0-9-]+\/)?$/);
  });

  it("can read repo sources for drift checks", () => {
    expect(existsSync(join(root, "..", "sdk", "src", "errors.ts"))).toBe(true);
  });
});
```

"use client";

import { Check, Copy } from "lucide-react";
import { useState } from "react";
import { Button } from "@/components/ui/button";

/** Copies `text`, or the text content of the nearest <pre> when `text` is omitted. */
export function CopyButton({ text, className }: { text?: string; className?: string }) {
  const [copied, setCopied] = useState(false);
  return (
    <Button
      variant="ghost"
      size="icon"
      aria-label="Copy"
      className={className}
      onClick={async (e) => {
        const value = text ?? e.currentTarget.closest("[data-copy-root]")?.querySelector("pre")?.innerText ?? "";
        await navigator.clipboard.writeText(value);
        setCopied(true);
        setTimeout(() => setCopied(false), 1500);
      }}
    >
      {copied ? <Check className="size-4" /> : <Copy className="size-4" />}
    </Button>
  );
}

"use client";

import { ChevronLeft, ChevronRight } from "lucide-react";
import Link from "next/link";
import { usePathname } from "next/navigation";
import { buttonVariants } from "@/components/ui/button";
import { docsNav } from "@/lib/docs-nav";

export function DocsPager() {
  const pathname = usePathname();
  const i = docsNav.findIndex((item) => item.href === pathname);
  if (i === -1) return null;
  const prev = docsNav[i - 1];
  const next = docsNav[i + 1];
  return (
    <div className="mt-12 flex justify-between border-t pt-6">
      {prev ? (
        <Link href={prev.href} className={buttonVariants({ variant: "ghost" })}>
          <ChevronLeft className="size-4" /> {prev.title}
        </Link>
      ) : (
        <span />
      )}
      {next && (
        <Link href={next.href} className={buttonVariants({ variant: "ghost" })}>
          {next.title} <ChevronRight className="size-4" />
        </Link>
      )}
    </div>
  );
}

- [ ] **Step 2: Write the pages**

**How it works** — from the README and the architecture spec:
- *Layout*: the bucket diagram; live key, `.ver2/o/<sha256 of key>/<versionId>` version objects, `.ver2/m/<key>` manifests.
- *Writes are journaled*: claim (`pending` op written to the manifest with compare-and-swap) → storage work → commit. Version objects are written with `If-None-Match: *` under a fresh ULID and never overwritten.
- *Guarded promote*: copy version → live with R2's `cf-copy-destination-if-match` / `-if-none-match` (standard `If-Match` on copy destinations is ignored by R2).
- *Direct writes*: detected by ETag; preserved as `external` versions before veR2 overwrites them; direct deletes become `external` delete markers.
- *Deletes*: logical; the live bytes are already a version; delete marker appended; DELETE takes no conditions on R2, so it is fenced by the lease.
- *Recovery*: outcomes `rolled-forward`, `rolled-back`, `stuck` (+ `in-progress`, `accepted-live`, `none`); never guess; `ver2 reconcile`, `--accept-live`.
- *Identity is SHA-256*, not ETag (ETags change on multipart copies and don't change on header-only edits).

**Configuration** — tables from `sdk/src/client.ts` and `sdk/src/storage/s3.ts`:
- `Ver2Options`: `store` (required), `meta` (default: manifests in the bucket), `namespace` (default `.ver2`), `leaseMs` (default 60000), `now`, `newId`.
- `S3StoreOptions`: `bucket`, `accountId`, `endpoint` (EU buckets: `https://<account>.eu.r2.cloudflarestorage.com`), `credentials`, `client`, `maxAttempts` (3), `requestTimeoutMs` (60000), `connectionTimeoutMs` (10000), `allowNonR2Endpoint`.
- CLI env vars (same as the CLI reference).
- Namespace rules: NFC, no control chars, non-empty segments, no `.`/`..`; keys inside the namespace are rejected.

**Guarantees and limitations** — the README table, then "Known limitations" from the architecture spec's limitations section (lines starting "Direct writes are preserved…" through "Unreferenced objects can accumulate…"), rewritten for users, linking to `docs/research/r2-behavior.md` on GitHub for evidence.
